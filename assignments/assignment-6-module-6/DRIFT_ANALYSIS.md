# Module 6.7: Data Drift Analysis & Alert Policy

## 1. Data Statement

- **Data Source:** The data used for this analysis is 100% SIMULATED. It is generated by `simulate_logs.py` and is explicitly marked in the database with `is_simulated = 1`.
- **Method:** We split the simulated history chronologically. The older 70% of the data served as the **Reference** (baseline), and the most recent 30% served as the **Current** (production) data.

## 2. Drift Analysis Results

We ran the **Kolmogorov-Smirnov (KS) test** on the model's output (`fraud_prob`).

- **What drifted:** The distribution of the fraud probabilities shifted significantly.
- **Why it matters:** Our simulated data deliberately introduced a spike in fraud probability over the last 6 days. The statistical test correctly flagged that the "Current" data is no longer behaving like the "Reference" data.
- **Score Distribution:** The recent average fraud probability is notably higher than the historical baseline (KS Statistic: 0.2395, P-value: 0.0000).

## 3. Recommended Actions

Because we detected **Prediction Drift**, the following steps are recommended:

1. **Investigate Inputs:** Check if the incoming `Amount` or `Time` features have shifted (Data Drift).
2. **Check the Pipeline:** Ensure the FastAPI service is correctly scaling the incoming data.
3. **Retraining Decision:** If the model is struggling with the new data, we should trigger the automated retraining pipeline (Module 6.8) to train a new model on the recent data.

## 4. Drift Alert Policy

| Indicator            | Condition                   | Level  | Owner          | Response Time   | Action                                                            |
| :------------------- | :-------------------------- | :----- | :------------- | :-------------- | :---------------------------------------------------------------- |
| **Prediction Drift** | KS Test p-value < 0.05      | High   | ML Engineer    | 1 Business Day  | Investigate data pipeline and review score distributions.         |
| **Data Drift**       | PSI > 0.25 for key features | Medium | Data Scientist | 2 Business Days | Compare feature distributions and decide if retraining is needed. |
| **Sample Size**      | < 100 records in the window | Info   | Developer      | None            | Skip drift test (insufficient data).                              |

## 5. Limits Note: What Drift Cannot Tell Us

Drift detection only looks at inputs and outputs; it does not know the _actual_ outcomes. A drift alert means the data has changed, not necessarily that the model is wrong. To know if the model is actually performing worse, we must collect **ground truth** (e.g., real confirmation of whether a transaction was fraud or not) and compare it to our predictions.
